# ctf-skill

## 목적

`ctf-skill`은 교육 목적의 승인된 CTF 대회 작업을 위한 의사결정 통제 정책입니다.

제품 파일은 `skills/ctf-solving/SKILL.md`입니다.
이 파일은 141줄로 구성되어 있습니다.
이 정책은 풀이 기법 목록이 아닙니다.
또한 성공이나 성능을 보장하지 않습니다.

정책의 목적은 제한된 시간과 정보 안에서
관찰한 증거에 따라 다음 판단을 일관되게 내리도록 돕는 것입니다.
작업자는 시작 조건, 가설, 위임, 재현, 수용 결과를
하나의 추적 가능한 흐름으로 관리할 수 있습니다.

## 의사결정 통제가 중요한 이유

CTF 작업에서는 초기 추측이 사실처럼 굳어지기 쉽습니다.
서로 다른 작업이 같은 가정을 중복 검증할 수도 있습니다.
로컬 결과와 실제 수용 결과가 혼동될 수도 있습니다.
환경 문제를 풀이 실패로 잘못 분류할 가능성도 있습니다.

의사결정 통제는 이런 혼동을 줄이기 위해
주장마다 근거의 출처와 적용 범위를 명확히 합니다.
검증 가능한 가설 수를 제한해 집중도를 유지합니다.
모순되는 증거가 나타나면 출처를 다시 확인합니다.
위임 작업은 격리하고 중복되지 않게 구성합니다.
마지막에는 깨끗한 로컬 재현과 실제 수용을 구분해 확인합니다.

## 적용 범주

정책은 증거에 따라 다음 여섯 범주로 작업을 라우팅합니다.

- crypto
- forensics
- misc
- pwn
- reverse
- web

범주는 기술을 지시하는 목록이 아닙니다.
현재 증거를 적절한 판단 흐름에 연결하기 위한 분류입니다.

## 핵심 기능

### 여섯 필드 대상 및 수용 계약

작업 시작 전에 대상과 수용 조건을 여섯 필드로 고정합니다.
이를 통해 무엇을 확인해야 하는지,
어떤 결과를 완료로 볼 것인지 먼저 합의합니다.

### 출처가 명시된 역량 원장

사용 가능한 역량과 제약을 기록할 때
각 항목의 출처와 신뢰 범위를 함께 관리합니다.
확인되지 않은 추정을 확정된 사실과 분리합니다.

### 최대 세 개의 반증 가능한 가설

동시에 유지하는 가설은 최대 세 개입니다.
각 가설은 관찰 가능한 증거로 반증할 수 있어야 합니다.
새 증거가 나오면 가설의 상태를 갱신합니다.

### 모순 및 출처 확인

관찰 결과가 기존 주장과 충돌하면
먼저 양쪽 증거의 출처와 적용 조건을 확인합니다.
모순을 숨기거나 임의로 한쪽을 채택하지 않습니다.

### 격리된 비중복 위임

위임 단위는 서로 독립적으로 검토할 수 있게 격리합니다.
동일한 질문을 여러 작업자가 반복하지 않도록 범위를 나눕니다.
각 결과는 원래 계약과 증거 원장으로 되돌려 연결합니다.

### 로컬 재현 후 실제 수용

결과는 먼저 깨끗한 로컬 상태에서 재현합니다.
그다음 실제 대회 수용 여부를 별도로 확인합니다.
로컬 재현만으로 최종 성공을 선언하지 않습니다.

## 결과 상태

모든 작업은 증거에 근거해 다음 다섯 상태 중 하나로 끝납니다.

- `solved`: 수용 계약을 충족했고 실제 수용이 확인됨
- `failed-with-valid-oracle`: 유효한 판정 근거 아래 실패가 확인됨
- `blocked-environment`: 환경 제약 때문에 필요한 검증을 진행할 수 없음
- `interrupted`: 외부 중단으로 판단 절차를 완료하지 못함
- `partial`: 일부 증거와 진전은 있으나 수용 계약을 충족하지 못함

상태 이름은 결과를 과장하지 않기 위한 보고 규칙입니다.
특히 `partial`과 `blocked-environment`는 `solved`로 간주하지 않습니다.

```text
ctf-skill/
├── README.md

    └── ctf-solving/
        └── SKILL.md
```

이 저장소가 배포하는 파일은 `README.md`와 제품 스킬 파일뿐입니다.

## 가져오기 및 설치 예시

아래 경로는 예시입니다.
에이전트마다 스킬 디렉터리와 로딩 방식이 다를 수 있습니다.

```sh
git clone <repository-url> ctf-skill
```

제품 파일을 사용하는 에이전트의 스킬 경로에 복사합니다.

```sh
mkdir -p <agent-skill-directory>/ctf-solving
cp ctf-skill/skills/ctf-solving/SKILL.md \
  <agent-skill-directory>/ctf-solving/SKILL.md
```

또는 에이전트가 저장소 경로를 직접 읽는 경우
`ctf-skill/skills/ctf-solving/SKILL.md`를 정책 파일로 지정합니다.
정확한 설치 위치는 해당 에이전트의 문서를 따릅니다.

## 승인된 안전 사용 예시

다음은 운영 기법이 아닌 상태 기록 예시입니다.

```yaml
authorization: "교육용 CTF 대회 운영자가 승인한 과제"
category: "misc"
target_contract:
  target: "대회가 제공한 과제"
  scope: "대회 규칙이 허용한 범위"
  evidence_source: "과제 설명과 제공 자료"
  acceptance_oracle: "대회 플랫폼의 공식 판정"
  stop_condition: "허용 범위 이탈 또는 환경 차단"
  reporting_rule: "다섯 결과 상태 중 하나로 기록"
capability_ledger:
  - claim: "제공 자료를 로컬에서 읽을 수 있음"
    provenance: "현재 작업 환경에서 직접 확인"
hypotheses:
  - statement: "수용 조건을 현재 증거로 평가할 수 있음"
    falsifier: "필수 자료 또는 공식 판정이 제공되지 않음"
delegation: "없음"
local_replay: "대기"
real_acceptance: "대기"
outcome: "partial"
```

이 예시는 승인, 범위, 근거, 중단 조건을 먼저 기록합니다.
실제 대상이나 운영 절차를 포함하지 않습니다.
증거가 바뀌면 관련 필드와 결과 상태를 함께 갱신합니다.

## 검증에서 관찰된 사항

격리된 GPT-5.6 Sol 의사결정 시나리오 열 건이 통과했습니다.
마지막 정확 범위 감사는 전면 승인으로 관찰되었습니다.
이는 해당 검증 조건에서 얻은 증거의 기록입니다.
다른 모델, 환경, 대회 또는 입력에서의 성능을 보장하지 않습니다.

## 승인 범위와 제한

이 정책은 교육 목적의 승인된 CTF 대회 작업에만 사용합니다.
대회 운영자가 정한 규칙, 대상, 시간, 계정 범위를 준수해야 합니다.
승인되지 않은 시스템이나 실제 서비스는 범위에 포함되지 않습니다.

정책은 판단과 보고 흐름을 통제하지만
과제별 정답, 기술적 절차 또는 성공 가능성을 제공하지 않습니다.
입력 증거가 불완전하면 결과도 제한될 수 있습니다.
환경이 검증을 막는 경우 이를 실패나 성공으로 바꾸어 보고하지 않습니다.
최종 수용 판단은 명시된 공식 판정 근거에 따릅니다.
